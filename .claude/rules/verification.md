# 규칙 — 검사를 어떻게 쓰나 (여기가 유일한 출처)

> 검사가 **무엇을 잡는지**는 [[hooks]] 에 있다. 이 파일은 **검사를 어떻게 추가하고 무엇을 증명해야 하는지**를 정한다.

## 1. 검사는 세 자리로 나뉜다 — 자리를 틀리면 안 돈다

| 잡을 것 | 자리 | 언제 도나 |
|---|---|---|
| 한 줄 정규식으로 판정되는 계약 위반 | `.claude/hooks/checks/uss-contract-lint.mjs` | fast(매 턴) |
| raw hex · 임의 값 | `.claude/hooks/checks/token-lint.mjs` | fast(매 턴) |
| **화면이 실제로 그렇게 도는가** | `harness/verify/step-*.mjs` | `--full`(커밋·패킷 직전) |

- **소스를 문자열로 훑는 규칙을 `harness/verify` 에 넣지 않는다.** 그건 린트다 → `uss-contract-lint`. verify 에 넣으면 fast 게이트에서 안 돌아 매 턴 방어가 사라진다.
- 반대로 **렌더·클릭·폴링으로만 드러나는 것을 정규식으로 흉내내지 않는다.** 그건 verify 다.

## 2. red 증명 의무 ⚠️ 이 규칙이 이 파일의 존재 이유다

**회귀 검사를 추가하면 대상 동작을 일부러 깨뜨려 red 가 나는 것을 실측한다.**

1. 검사를 추가한다 → green 을 확인한다
2. **막으려는 버그를 되돌린다** → 그 검사가 **red** 가 나는지 본다
3. 코드를 되돌린다 → green 복귀
4. 실패 문구를 그대로 적는다: 커밋 메시지 + `harness/review/<항목ID>.json` 의 `verify` 필드

**2단계를 못 했으면 "고정했다"·"막았다"·"잠갔다" 라고 쓰지 않는다.** "검사를 추가했다(red 미확인)" 이라고 쓴다.

> 이 규칙이 없어서 실제로 벌어진 일: `<button[^>]*disabled[^>]*>` 가 class 의 `disabled:pointer-events-none` 에 걸려 **활성 버튼도 통과**했고 step-4~5-2 내내 아무것도 안 잡았다. 폴링 회귀 검사는 마운트를 갈아버려 **버그 소스로도 전건 통과**했다.

## 3. 근거 절 의무

각 `section()` 은 근거를 단다. 셋 중 하나여야 한다.

```
section('진행률 total null 분기 (03 §7-3)');
section('종료 처리는 Job 당 한 번 (01 §8-1)');
section('실행 버튼 잠금 조건 2개 (사용자 결정 2026-08-09)');
```

**근거를 못 다는 검사는 만들지 않는다.** 명세에도 결정에도 없는 동작을 검사로 굳히면, 그 검사가 다음 세션에 요구사항으로 승격된다.

> 이 규칙이 없어서 실제로 벌어진 일: 리뷰어가 든 *예시*("다른 관리자가 Job 을 돌리면")를 시나리오로, 다시 요구사항으로 부풀려 한 세션에서 가장 오래 붙잡았다. `01`·`03`·`04` 어디에도 없는 동작이었다.

## 4. 검사가 헛도는 세 가지 패턴 — 새 검사를 쓸 때마다 대조한다

| 함정 | 틀린 모양 | 맞는 모양 |
|---|---|---|
| **존재로 셈** | `html.includes('토스트 문구')` | 개수를 센다 — `eq('토스트 1개', count, 1)` |
| **부등호** | `check('최소 5회', n >= 5)` | 정확히 — `eq('호출 횟수', n, 5)` |
| **마운트 리셋** | 스텝마다 새로 마운트 | **한 마운트 안에서** 클릭→종료→재개를 이어 붙인다 |

`>=`·`includes`·`length > 0` 을 쓰려는 순간 멈추고 정확한 수를 셀 방법을 먼저 찾는다. 버그 쪽 값이 부등호를 통과하면 검사는 없는 것과 같다.

## 5. 탐색 상한 — 3회

원인을 못 밝힌 채 **3회** 시도했으면 멈춘다. 4회째를 시작하지 않는다.

1. `build-state.json.probes[항목ID]` 를 올린다
2. `notes` 에 `unresolved` 태그로 **미규명 사실 + 지금까지 배제한 가설 + 좁혀진 조건**을 적는다
3. 다음으로 넘어간다

게이트 red 의 자가수정 한도(3회)와 같은 취급이다. 원인 추적만 상한이 없을 이유가 없다.

## 6. 검사를 늘릴 때의 순서

1. 무엇을 막을 건지 한 줄로 쓴다 → 근거 절이 있는지 본다(§3). 없으면 만들지 않는다
2. 자리를 고른다(§1)
3. 쓴다 → green
4. **깨뜨린다 → red 확인**(§2)
5. 복구 → green → 커밋 메시지에 red 문구를 적는다
