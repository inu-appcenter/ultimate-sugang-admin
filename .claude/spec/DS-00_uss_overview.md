# USS 백오피스 — 디자인 방향 (DS-00)

> 이 문서가 시각 **방향**을 정한다. 구체적인 값은 `DS-01`, 강제되는 규칙은 `.claude/rules/ui-conventions.md` 에 있다.
> ⚠️ Gravit 의 `DS-00_overview.md` 는 **승계하지 않는다.** 본 문서가 대체한다.

**문서 버전**: v1.0 (2026-08-07)

---

## 1. 한 줄 정의

**USS 백오피스** — 모의 수강신청 서비스의 학사과용 강의 데이터 관리 도구.

## 2. 사용자 / 사용 환경

| 항목 | 내용 |
|---|---|
| 사용자 | 학사과 담당자 **수 명** |
| 사용 환경 | 사무실 데스크톱 |
| 기술 친숙도 | **보통** — 개발자·운영 전문가가 아니다 |
| 사용 빈도 | **낮음** — 학기당 수 회. 매일 쓰는 도구가 아니다 |

> ⚠️ **사용 빈도가 낮다는 점이 디자인 방향을 결정한다.** 매일 쓰는 도구는 학습된 밀도가 이득이지만, 학기당 몇 번 여는 도구는 **매번 처음처럼 읽힌다.** 정보 밀도보다 **즉시 이해**가 우선이다.

## 4. 톤 & 레퍼런스

| 항목 | 값 |
|---|---|
| 레퍼런스 | **토스(Toss)** 계열 |
| 톤 | 사용자 친화적·깔끔·직관적 |
| 강조 수단 | **크기·굵기·여백** (색 아님) |
| 분위기 | 차분하되 딱딱하지 않게. 장식 요소 없음 |

### 4-1. 디자인 원칙 (5)

1. **크기로 계층을 만든다.** 제목·수치·설명의 크기 차이를 크게 둔다. 색으로 구분하지 않는다.
2. **Border 대신 Surface + Shadow.** 카드는 보더 없이 배경 대비와 매우 약한 그림자로 층을 만든다.
3. **여백을 아끼지 않는다.** 카드 내부 padding 24px 기준.
4. **색은 5~10%만.** Primary 는 CTA·활성 상태에만. 화면 대부분은 흰색과 회색이다.
5. **문장은 짧고 구어체로.** 한 문장 15~25자. 단, **비가역 경고는 예외**(§6).

## 5. 채택 / 미채택 (토스 25축 대비)

### 5-1. 채택

| 축 | 적용 |
|---|---|
| 타이포 위계·숫자 우선 | 카드 수치를 32px Bold 로. 라벨보다 숫자를 먼저 읽히게 |
| Border 최소 → Shadow | 카드 3장 보더 제거 |
| Radius 12~16 | card 14 / button 10 / modal 16 |
| 여백 24 기준 | 카드 padding 24, 카드 간격 24 |
| Blue tint gray | 중립색 전체에 푸른 기 |
| 색 절제·크기로 강조 | Primary 는 CTA 2개 + 활성 탭에만 |
| Primary 1개만 강하게 | 화면당 채워진 버튼 1개. 나머지는 Outline·Ghost |
| Line icon 20~24 | lucide-react |
| 150~250ms motion | 모달·토스트·인라인 확장 |
| Left align | 텍스트 전부 좌측. 수치 컬럼만 우측 |
| 짧은 구어체 | §6 |
| Fill 입력창 | 로그인 폼 |

### 5-2. 미채택 (구조상 불가 — 사유 명시)

| 축 | 사유 |
|---|---|
| **정보 단계적 노출** | `D11` 이 미리보기를 배제했고, 상세는 **인라인 확장**으로 확정(`01 §6-5`). 화면을 늘리면 `D8`(화면 2개) 위반 |
| **Divider 최소화** | 이력 테이블 7컬럼 × 10행. divider 를 빼면 행 추적이 불가능해진다. **테이블 내부는 얇은 divider 유지** |
| **한 화면 한 과업** | `SYNC_MAIN` 은 카드 2 + 테이블 1 이 한 화면에 있어야 한다. 분해하면 학기 설정과 적재 현황을 오가야 한다 |

### 5-3. 조정 채택

| 축 | 조정 내용 |
|---|---|
| **카드 하나 = 기능 하나** | 카드 2(적재 데이터)는 상태·이력·요약·액션 4가지를 담지만 **주제가 하나**(적재 데이터)이므로 분리하지 않는다. 토스가 금지하는 건 무관한 기능의 혼재이지, 한 주제의 상태와 액션을 묶는 것이 아니다 |
| **여백 극대화** | **카드는 여백을 키우고, 테이블 내부는 밀도를 유지**한다. 테이블도 카드로 감싸(padding 24 / radius 14 / 보더 없음) 바깥 언어는 통일하되, 행 높이는 표준으로 둔다 |

## 6. 문장 어조 (Voice)

**구어체를 기본으로 한다.** 단 아래 예외가 있다.

| 구분 | 어조 | 예 |
|---|---|---|
| 기본 | 구어체 | 표시 학기를 변경했어요. / 데이터를 갱신할까요? |
| 안내 문구 | 구어체 | 서비스 화면에 보이는 학기예요. |
| 에러 | 구어체 | 아이디나 비밀번호가 맞지 않아요. |
| **M4 (전량 삭제)** | **격식체 유지** | 기존 데이터를 모두 삭제합니다 / 이 작업은 되돌릴 수 없습니다. |

> **M4 예외 근거**: 장바구니·수강신청까지 영구 삭제하는 **비가역 작업**이다. 구어체는 위험도를 가볍게 만든다. 어조 통일보다 **오조작 방지**가 우선한다.

### 6-1. 작성 규칙

- 한 문장 **15~25자**. 두 문장을 넘기지 않는다.
- `~하시겠습니까?` → `~할까요?` / `~되었습니다` → `~했어요` / `~없습니다` → `~없어요`
- 과도한 친근함은 피한다. 이모지·감탄사 사용 금지.

## 7. 화면 구성

```
🔐 /login    ADMIN_LOGIN   로그인 (헤더 없는 독립 레이아웃)
🗂 /         SYNC_MAIN     강의 데이터 관리
```

모달 5종(M1~M5)은 별도 라우트가 없다. 상세는 `01 §3, §7`.
