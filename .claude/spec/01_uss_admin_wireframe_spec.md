# USS 백오피스 와이어프레임 명세서

> 모의 수강신청 서비스(USS)의 학사과용 백오피스. 강의·시간표 데이터 적재와 표시 학기 설정을 담당한다.
> 이 문서가 **화면·동작·상태 전이**를 정한다. API 계약은 `03`, 프론트 통합은 `04`, 시각 토큰은 `DS-01` 을 따른다.

---

## 1. 개요

### 1-1. 대상 사용자

학사과 담당자. 소수(수 명). 데스크톱 전용, 라이트 모드, 1280px+ 단일 폭.

### 1-2. 백오피스가 하는 일

| # | 기능 | 설명 |
|---|---|---|
| 1 | 표시 학기 설정 | 서비스 화면에 노출되는 `연도 + 학기` 라벨 변경. **강의 데이터와 무관** |
| 2 | 데이터 업데이트 | 학교 API에서 강의·시간표를 수집해 `courses`·`course_schedules`에 적재 |
| 3 | 이력 조회 | 과거 적재 작업의 결과·변경 상세 확인 |

### 1-3. 핵심 원칙

- `courses` 테이블에는 **항상 단일 학기 데이터만** 존재한다.
- 적재 전략(upsert / 전체 교체)은 **서버가 판정**한다. 관리자는 적재할 학기만 지정한다.
- 표시 학기 설정과 데이터 적재는 **완전히 독립**이다. 서로를 트리거하지 않는다.

## 2. 용어

| 용어 | 정의 |
|---|---|
| **표시 학기** | `semester_setting`에 저장된 라벨. 프론트 노출용. 데이터와 무관 |
| **적재 학기** | `courses`에 실제로 들어 있는 `academic_year` + `term` |
| **Job** | 데이터 업데이트 작업 1회. `course_sync_job` 1행 |
| **UPSERT** | 적재 학기 == 대상 학기. 신규/수정/폐강 3-way diff 적용 |
| **REPLACE** | 적재 학기 != 대상 학기. 기존 데이터 전량 삭제 후 신규 적재 |
| **폐강** | UPSERT 시 API 응답에 없고 DB에만 있는 과목. `status = CLOSED`로 전환(물리 삭제 아님) |

```
├──────────────────────────────────────────────────────────┤
│                                                          │
│   ┌────────────────────────────────────────────────┐     │
│   │                                                │     │  ← 컨텐츠
│   │              max-width 1024px                  │     │     padding 32px
│   │                                                │     │
│   └────────────────────────────────────────────────┘     │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

| 요소 | 사양 |
|---|---|
| Header 높이 | 56px, 하단 1px border |
| 좌측 | 서비스명 "USS 관리자" (클릭 시 `/`) |
| 우측 | 관리자 이름 + Ghost Button "로그아웃" |
| 콘텐츠 | max-width 1024px, 중앙 정렬, padding 32px |

> 카드는 **보더 없이** `bg-surface` + `shadow-card` + `bg-page` 대비로 층을 만든다. 카드 내부 padding 24px, 카드 간격 24px. 값은 `DS-01`, 방향은 `DS-00 §4-1`.

```
┌──────────────────────────────────────────────────────────────┐
│  강의 데이터 관리                                             │
│                                                              │

│  │  표시 학기                                             │  │
```

### 6-2. 카드 1 — 표시 학기

| 항목 | 내용 |
|---|---|
| 값 | `{academicYear}학년도 {termName}` |
| 보조 문구 | "서비스 화면에 보이는 학기예요." (`text-caption`, `fg-secondary`) |
| 버튼 | Outline Button "학기 설정" → **모달 M1** |

> 이 카드의 값과 카드 2의 적재 학기는 **다를 수 있다.** 정상 상태이며 경고를 띄우지 않는다.

### 6-3. 카드 2 — 적재 데이터

| 행 | 내용 | 데이터 없을 때 |
|---|---|---|
| 학기·건수 | `{학년도} {학기}` + 강의·시간표 건수 (`text-metric`) | "아직 적재된 데이터가 없어요." |
| 마지막 업데이트 | `{일시}` + Status Badge | "업데이트 이력이 없어요." |
| 변경 요약 | `신규 {n} · 수정 {n} · 폐강 {n}` | 숨김 |
| 버튼 | Primary Button "데이터 업데이트" → **모달 M2** | 동일 |

#### Status Badge

| 값 | 라벨 | variant |
|---|---|---|
| `SUCCESS` | 성공 | success |
| `FAILED` | 실패 | danger |
| `RUNNING` | 진행 중 | warning |

`RUNNING` job이 존재하면 [데이터 업데이트] 버튼은 **비활성** + 툴팁 "업데이트가 진행 중이에요."

### 6-4. 이력 테이블

| 컬럼 | 폭 | 데이터 | 비고 |
|---|---|---|---|
| 일시 | 150px | `startedAt` | `YYYY-MM-DD HH:mm` |
| 대상 학기 | 120px | `{연도}-{학기명}` | |
| 방식 | 80px | `strategy` | Badge — UPSERT=갱신(info) / REPLACE=교체(accent) |
| 상태 | 80px | `status` | Status Badge |
| 신규 | 70px | `createdCount` | 우측 정렬. 실패 시 `-` |
| 수정 | 70px | `updatedCount` | 동일 |
| 폐강 | 70px | `closedCount` | 동일. REPLACE는 항상 `0` |

- 페이지 크기 **10행 고정**
- 테이블은 **카드로 감싼다**(padding 24 / radius 14 / 보더 없음 / `shadow-card`). 내부 행 높이는 표준 유지 — `DS-00 §5-3`
- 행 구분은 **얇은 divider**(`border`)만. 카드 보더는 쓰지 않는다
- 행 hover 시 배경 강조 + `cursor: pointer`
- 행 클릭 → **인라인 확장** (별도 페이지 이동 없음)
- 확장은 **동시에 1행만**. 다른 행 클릭 시 이전 행은 접힘

### 6-5. 인라인 확장 영역

```
│ 08-05 14:22  │2026-1학기│갱신 │성공│ 12 │ 45 │  3      │
├──────────────────────────────────────────────────────────┤
│   실행자  김학사        소요  00:01:47                   │
│   수집    강의 1,215건 · 시간표 2,891건                  │
│                                                          │
│   [ 신규 12 ] [ 수정 45 ] [ 폐강 3 ] [ 경고 2 ]          │  ← 탭
│   ┌────────────────────────────────────────────────┐     │
│   │ 학수번호     │ 과목명          │ 변경 내용     │     │
│   ├────────────────────────────────────────────────┤     │
│   │ 0000018001   │ 신소재공학실험  │ 강의실        │     │
│   │              │                 │ 4호관301      │     │
│   │              │                 │ → 4호관305    │     │
│   └────────────────────────────────────────────────┘     │
│                    [ 더 보기 ]                           │
└──────────────────────────────────────────────────────────┘
```

| 요소 | 사양 |
|---|---|
| 메타 행 | 실행자 · 소요 시간 · 수집 건수 |
| 탭 | 신규 / 수정 / 폐강 / 경고. 건수 0인 탭은 **비활성** |
| 기본 탭 | 건수가 0이 아닌 가장 왼쪽 탭 |
| 목록 | 최초 10건. [더 보기]로 10건씩 추가 |
| 변경 내용 | 수정 탭만 `{필드명} {before} → {after}` 표시. 여러 필드면 줄바꿈 |

#### 경고 탭

enum 미매핑 등으로 **적재하지 못한 항목**을 표시한다. Job은 실패시키지 않는다.

| 컬럼 | 내용 |
|---|---|
| 학수번호 | `haksuCode` |
| 사유 | 예: "미등록 이수구분 코드: 99" |

#### 실패한 Job의 확장 영역

```
│   실행자  김학사        소요  00:00:12                   │
│   ⚠ 실패 사유                                            │
│   학교 API 호출 실패 (429 Too Many Requests) — PAGE 7    │
│                                                          │
│   변경 사항은 적용되지 않았어요.                         │
└──────────────────────────────────────────────────────────┘
```

## 7. 모달

| ID | 이름 | variant | 폭 |
|---|---|---|---|
| M1 | 학기 설정 | default | 400px |
| M2 | 데이터 업데이트 — 학기 선택 | default | 400px |
| M3 | 업데이트 확인 (UPSERT) | default | 400px |
| M4 | 업데이트 확인 (REPLACE) | **destructive** | 480px |
| M5 | 로그아웃 확인 | default | 400px |

### 7-1. M1 — 학기 설정

```
┌──────────────────────────────────────┐
│  표시 학기 설정                   ✕  │
├──────────────────────────────────────┤
│  서비스 화면에 보이는 학기예요.      │
│  강의 데이터에는 영향을 주지 않아요. │
│                                      │
│  연도   [ 2026 ▼ ]                   │
│  학기   [ 2학기 ▼ ]                  │
├──────────────────────────────────────┤
│                     [취소]  [저장]   │
└──────────────────────────────────────┘
```

| 항목 | 사양 |
|---|---|
| 연도 옵션 | 현재 연도 ±2 (5개) |
| 학기 옵션 | 1학기 / 여름계절학기 / 2학기 / 겨울계절학기 |
| 초기값 | 현재 설정값 |
| [저장] | 즉시 반영 + Success 토스트 "표시 학기를 변경했어요." |
| 변경 없음 | [저장] 비활성 |

### 7-2. M2 — 데이터 업데이트 (학기 선택)

```
┌──────────────────────────────────────┐
│  데이터 업데이트                  ✕  │
├──────────────────────────────────────┤
│  적재할 학기를 골라주세요.           │
│                                      │
│  연도   [ 2026 ▼ ]                   │
│  학기   [ 1학기 ▼ ]                  │
│                                      │
│  현재 적재  2026학년도 1학기         │
├──────────────────────────────────────┤
│                     [취소]  [다음]   │
└──────────────────────────────────────┘
```

| 항목 | 사양 |
|---|---|
| 초기값 | **현재 적재 학기**. 적재 데이터가 없으면 표시 학기 |
| [다음] | 전략 판정 요청 → 응답에 따라 M3 또는 M4로 전환 |
| 판정 중 | [다음] 비활성 + spinner |

> 전략 판정은 API 수집 **이전**에 이루어진다. `courses`의 현재 학기와 선택값만 비교하므로 즉시 응답한다.

### 7-3. M3 — 업데이트 확인 (UPSERT)

선택 학기 == 현재 적재 학기.

```
┌──────────────────────────────────────┐
│  데이터를 갱신할까요?             ✕  │
├──────────────────────────────────────┤
│  2026학년도 1학기 데이터를           │
│  최신 상태로 갱신할게요.             │
│                                      │
│  · 새로 생긴 과목은 추가돼요.        │
│  · 바뀐 과목은 수정돼요.             │
│  · 사라진 과목은 폐강 처리돼요.      │
│  · 장바구니·수강신청은 그대로예요.   │
├──────────────────────────────────────┤
│                     [취소]  [갱신]   │
└──────────────────────────────────────┘
```

### 7-4. M4 — 업데이트 확인 (REPLACE)

선택 학기 != 현재 적재 학기. **destructive**.

```
┌────────────────────────────────────────────┐
│  기존 데이터를 모두 삭제합니다          ✕  │
├────────────────────────────────────────────┤
│  현재   2026학년도 1학기                   │
│  변경   2026학년도 여름계절학기            │
│                                            │
│  다음 데이터가 영구 삭제됩니다.            │
│    강의        1,203건                     │
│    시간표      2,847건                     │
│    장바구니       87건                     │
│    수강신청       41건                     │
│                                            │
│  이 작업은 되돌릴 수 없습니다.             │
│                                            │
│  확인을 위해 아래를 입력하세요             │
│  2026-여름계절학기                         │
│  [                                    ]    │
├────────────────────────────────────────────┤
│                       [취소]  [삭제 후 적재]│
└────────────────────────────────────────────┘
```

| 항목 | 사양 |
|---|---|
| 삭제 건수 | 전략 판정 응답에서 수신 |
| Strict Match | `{연도}-{학기명}` 정확히 일치해야 실행 버튼 활성 |
| 실행 버튼 | Destructive variant |
| ESC / 외부 클릭 | 닫힘 + 입력값 초기화 |
| 적재 데이터 없음 | 삭제 건수 전부 0 → **M4 대신 M3 문구 변형** 사용 (§7-5) |

### 7-5. 최초 적재 (DB 비어 있음)

`courses`가 비어 있으면 삭제할 것이 없으므로 destructive가 아니다.

```
┌──────────────────────────────────────┐
│  데이터를 적재할까요?             ✕  │
├──────────────────────────────────────┤
│  2026학년도 1학기 데이터를           │
```

## 8. Job 상태 전이

```
        [확인 모달 실행]
              │
              ▼
          RUNNING ──┬──▶ SUCCESS
                    │
                    └──▶ FAILED
```

미리보기 단계가 없으므로 중간 상태는 `RUNNING` 하나다.

### 8-1. 실행 중 화면

```
┌────────────────────────────────────────────────────────┐
│  적재 데이터                                           │
│  ⟳ 업데이트 진행 중 · 강의 수집 3/12 페이지            │
│                                                        │
│                        [ 데이터 업데이트 ]  ← 비활성   │
└────────────────────────────────────────────────────────┘
```

| 항목 | 사양 |
|---|---|
| 폴링 주기 | 2초 |
| 진행 표시 | `{단계} {현재}/{전체}` — 단계: 강의 수집 / 시간표 수집 / 적재 |
| 완료 시 | 폴링 중단, 카드·이력 갱신, Success 토스트 |
| 실패 시 | Error 토스트 + 이력 최상단 행 자동 확장 |
| 새로고침 / 재진입 | `RUNNING` job 있으면 폴링 자동 재개 |

### 8-2. 동시 실행

`RUNNING` job이 존재하는 동안 새 업데이트 요청은 거부한다. (버튼 비활성 + 서버 409)

### 8-3. 실패 처리

| 단계 | 실패 시 |
|---|---|
| 수집 중 | 적재 미실행. DB 무변화 |
| 적재 중 | 청크 단위 커밋. 적용된 부분은 유지되며 이력에 "부분 적용" 표시 |

> 부분 적용 상태에서 재실행하면 UPSERT는 나머지를 마저 처리한다. REPLACE는 삭제가 이미 끝난 상태이므로 재실행 시 최초 적재로 동작한다.

## 11. 실측 확인 항목

연동 초기 1회 검증이 필요하며, 결과에 따라 본 명세가 수정될 수 있다.

| # | 항목 | 영향 |
|---|---|---|
| 1 | `MOD_DATE`에 과거 날짜(`{연도}0101`) 입력 시 정상 동작 | 전량 수집 가능 여부 |
| 2 | `YEAR` 파라미터 필터 동작 | 수집량 |
| 3 | `TERM_CODE` 파라미터 필터 동작 | 수집량. 미동작 시 앱에서 필터링 |
| 4 | `TERM_CODE` 실제 반환값이 `10/20/30/40`인지 | enum 매핑 |
| 5 | 두 API의 `TERM_CODE` 체계 동일 여부 | 강의-시간표 조인 |
| 6 | HTTP 메서드 (POST / GET) | 클라이언트 구현 |
| 7 | 페이지당 최대 건수 | 진행률 표시 |
| 8 | 호출 서버 IP가 등록 IP와 일치 | 연동 가능 여부 |

> `03_uss_admin_api_spec.md` §11-1이 동일 항목을 담고 있으며, 중복 관리를 피하기 위해 **`03`을 SoT로 삼는다.** 본 절은 참조용으로 유지한다.

## 부록 A. 확정 사항 (D1~D12)

| # | 결정 |
|---|---|
| D1 | 항상 전량 수집. `MOD_DATE`는 `{연도}0101` 고정, 학기는 `TERM_CODE`로 필터링 |
| D2 | `max_capacity`(신규 기본 40)·`current_enrollment`는 서비스 소유. UPSERT 시 UPDATE 대상에서 제외 |

| D7 | Oracle 직결은 **학생 인증 전용**(유지). 강의 데이터는 INTIP HTTP API |

| D10 | 표시 학기 설정은 데이터 적재와 완전 독립 |
| D11 | 미리보기(2단계 적용) 미채택. 확인 모달 후 즉시 실행 |
